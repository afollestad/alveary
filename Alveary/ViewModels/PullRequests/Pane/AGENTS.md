## Pull Request Detail Pane

These instructions cover `Alveary/ViewModels/PullRequests/Pane/` — the pane session, its detail and diff loads, and the remote-change observer that refetches them. The list behind it is `Alveary/ViewModels/PullRequests/AGENTS.md`; the session/generation lifecycle every contextual pane follows is `Alveary/ViewModels/AGENTS.md`; `Alveary/Views/PullRequests/Pane/AGENTS.md` owns the rendering half.

**Keep a rule here only when the code that would violate it is not the code that documents it.** `PullRequestPaneLoad`'s token match, `cancelPaneLoads(except:)`'s reason for not keying off `activePaneTarget`, `resumeIncompleteLoads`' interrupted-versus-failed split, `loadDetail`'s `reportsFailure:`, `PullRequestsViewModel+PaneLoading.swift`'s header on writing only through `updateSession(_:generation:_:)`, and the synchronous-observation and debounce rationales in `PullRequestsViewModel+RemoteChanges.swift` each carry theirs.

- **Only the open pane keeps its loads.** The `cancelPaneLoads` helpers are here, but all three callers — `openPane`, `deactivatePane(_:generation:)`, `dismissPane` — are in `PullRequestsViewModel.swift` one scope up. A pane lifecycle path added there that skips them leaves loads running against a session nobody is looking at.
- **Cancellation is the concurrency bound — do not add a semaphore or numeric cap.** One live pane means at most two requests in flight and a list load at most three (`requiredBuckets`, deduped by `inFlightBuckets`), so no cap scoped to pane loads could bind first. Anything bounding pull request traffic more broadly belongs at `GitHubPullRequestsService.runGitHubCLI`, which the host tools and proposal coordinator also pass through.
- **A cancelled load must leave the session untouched.** Both `catch` blocks check `Task.isCancelled` before writing, because shell teardown wraps cancellation in a `PullRequestsServiceError` rather than rethrowing it. That is also what leaves the session *detectably incomplete* for `resumeIncompleteLoads`.
- **The retry buttons live in the views, not in a reopen.** The Overview's error banner and the Changes tab's empty state call `retryDetailLoad()` / `retryDiffLoad()`; `.tooLarge` gets no button, because an identical request cannot pass a fixed cap.
- **A pull request changed outside the pane reaches it through `.pullRequestChangedOnGitHub`.** Nothing in `PullRequestDetail` or the list's review-requested bucket is derived locally, so a review confirmed on the transcript card and every `alveary_host` mutation land only as a refetch.
    - **Do not make `openPane` refetch a retained session instead.** Reopening stays instant, and refetching there would also retry a failed leg, which only the explicit retries may.
