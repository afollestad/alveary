## Sidebar Rows

These instructions cover `Alveary/Views/Sidebar/Rows/` — project rows, thread rows, section header rows, the shared disclosure caret, the thread context menu, and inline rename and cleanup.

> **READ FIRST:** Focus and keyboard rules are centralized in **Focus And Keyboard Coordination** in `Alveary/Views/AGENTS.md`. The bullets below stack on top of that parent contract — they are not a replacement for it.

**Keep a rule here only when the code that would violate it is not the code that documents it.** Mechanism whose only reader is its own file belongs in a doc comment: `SidebarDisclosureCaret`, `SidebarDisclosureCaretToggle`, `SidebarSectionHeaderDisclosure`, `sidebarThreadCleanupButtonVisibility`, and `SidebarThreadRowPresentation` each carry theirs.

- **`SidebarThreadRow` never stores an `AgentThread`.** `SidebarView.sidebarThreadRow(_:)` builds a `SidebarThreadRowPresentation` from the render snapshot and passes that down, covering the row *and* its lazily-evaluated context menu; the row's own `@State` re-renders outlive the row's model. Row actions still take the live model, because they run from a click.

- `SidebarProjectRow`'s leading icon `Button` is load-bearing for click-to-expand:
    - **Action:** toggles expansion, never project activation. `onToggleExpanded` stays the sole action; activation lives on the sibling content affordance plus the row's transparent background tap target, so dead space inside selected-row chrome still opens the project.
    - **Stationary animated toggle:** keep the explicit expansion animation for child reflow and caret rotation, and keep drag-geometry modifiers structurally stable across expansion — conditional geometry changes only its emitted preference value, because adding or removing the modifier makes SwiftUI `List` transition the header itself.
    - **Fixed icon:** always render the folder glyph; never swap it for a disclosure chevron.
    - **Inline disclosure:** `SidebarDisclosureCaret` after the title, shared with `SidebarSectionHeaderRow`; its fixed slot stays reserved while hidden so visibility never shifts truncation. `SidebarDisclosureCaretToggle` documents why the project row passes none — do not give this caret a tap gesture again.
    - **Collapsed keeps its caret:** a collapsed row shows the caret unconditionally — it is the only sign the row hides content, and `isSidebarDragInteractionInFlight` (which documents what every row owes a drag in flight) does not reach it because every toggle path is drag-guarded. Hover, the flash, and drag suppression govern the expanded state alone.
    - **Flash on unattended toggle:** an expansion change with the pointer away shows the caret briefly, then fades it, so keyboard and programmatic toggles are not silent; hover-driven toggles already show it, and drag suppression outranks the flash.
    - **Hit region:** keep the fixed 16×16 frame with `.contentShape(Rectangle())` — a `.plain` `Button` otherwise hit-tests the SF Symbol's intrinsic outline, and edge clicks miss.
    - **Accessibility:** explicit `.accessibilityLabel` (`Expand <project>` / `Collapse <project>`); VoiceOver otherwise reads the raw symbol name.
- `SidebarSectionHeaderRow` collapses its whole section when given a `SidebarSectionHeaderDisclosure`:
    - **Collapse is in memory, keyed by section identity.** `Projects`, `Tasks`, and every custom section collapse; `Pinned` passes no disclosure and stays inert. `SidebarView.collapsedSections` is session-scoped `@State` like `expandedProjects`, seeded for fixtures through `initialCollapsedSections`, and holds `SidebarCollapsibleSection` values so a custom section's state survives a rename. A collapsed section hides only its own rows — never a following section's header.
    - **The whole row is the target.** Title, the gap after it, the caret, and the dead space all toggle — deliberately unlike a project row, where only the folder toggles and everything else activates the project, because a section header has nothing to activate. This is the one caret that takes clicks. The tap is the title row's own `contentShape`, never a backing rectangle — `Text` hit-tests its own frame, so a background layer never sees a click on the title — and it stops at the title row so a click in the section gap above it does nothing. The caret and the trailing action button are children and keep their own clicks; the `+` button must never toggle. The toggle itself is a zero-distance drag rather than `onTapGesture` — `rowToggleGesture` owns why, and `Alveary/Views/Sidebar/Drag/AGENTS.md` owns what the drag depends on it for.
    - **Reveal explicitly.** Beyond `revealProject`'s own callers, `syncExpansionWithSelection` reopens the section a routed selection landed in via `sidebarSectionToExpand`, and the drop finalizer the section a drop landed in. Unlike `sidebarProjectPathToExpand`, selecting a project row *does* reopen its section — traversal may rest on a collapsed row, never inside a collapsed section.
    - **Accessibility:** the title carries `.isHeader` plus `.isButton` and a dynamic `Collapse <title>` / `Expand <title>` label; the caret owns the tooltip.
- `SidebarProjectRow`'s trailing new-thread button: hidden and non-hit-testable until row hover (even while selected); only pointer hover over the button itself shows the circular background; keep its center aligned with `SidebarSectionHeaderRow`'s add-project button; hide the hover-only icon from accessibility and keep `New Thread` as a named custom action on the always-present activation element.
- Project rows are single-line — do not reintroduce branch/path/local subtitles — and share `SidebarRowMetrics.topLevelAndThreadContentHeight` with thread rows; no extra vertical padding.
- Anything row-mounted that lines up with a `List` section header's leading edge adds `SidebarProjectListMetrics.plainRowLeadingCorrection`: the `Pinned`/`Projects`/`Tasks` headers, their placeholders, and the top-level rows' icon column. Do not retune one of them alone.
- While a draft is mounted, its project row is the effective selection for highlighting and keyboard navigation; every New Thread entry point reuses that draft and may reassign its project in place. Drafts never reach rows at all — `Alveary/Views/Sidebar/AGENTS.md` owns that exclusion.

### Rename And Cleanup

- Inline editing is Finder-style everywhere: a `TextField` swaps in for the label. Threads track theirs with `editingThreadID`, custom section headers with `editingSectionID`, and the pending new-section row with `isCreatingSection`.
- **`SidebarView.isSidebarInlineEditingActive` is the single gate for all three.** Every "Rename..." entry (context menu, VoiceOver rotor via `canBeginRename`, the ⏎ key path), every drag source, the drag-cancel observer, the thread-order animation, and the empty-area menu read it — not `editingThreadID` alone, which cannot see a section rename. Swapping the editing target mid-edit left the previous row stuck without an input field, because the TextField unmount/mount within one SwiftUI update pass did not converge; users finish the in-flight edit (Enter / Escape / click away) first.
- **Seed a rename field on appear as well as on change.** A header that mounts already editing — SwiftUI rebuilding it because the section list changed around it — gets no `onChange`, and an unseeded field silently blanks the name being edited.
- Threads with an active scheduled run keep Archive and Delete visible but disabled, explained with the shared settings-style hover tooltip; hovering the cleanup target directly replaces the glyph with `nosign`. Unpin is never disabled.
- `SidebarThreadRow` renders on a single line; do not reintroduce a branch or worktree subtitle.
- `SidebarThreadRow` status indicator layout:
    - Keep the trailing status slot size-locked and center-aligned with the project/header action buttons, the row framed to `maxWidth: .infinity`, and the invisible leading slot so thread titles align with project names.
    - `.busy` uses a spinner in the same fixed frame as the colored dot (`8×8` today) so status changes cannot change row height or nudge the label.
    - Task threads created by a scheduled run show the scheduled glyph before the worktree glyph and status/cleanup control, matching the worktree glyph's size, color, and hover-help styling, with a `Scheduled task` accessibility label.
    - Threads with `useWorktree` show a rotated branch glyph before the status/cleanup frame with a 6pt explicit gap; its hover tooltip shows the worktree path, or `Worktree path not created yet`.
    - Keep the title gap, glyphs, and status/cleanup frame in a fixed-width trailing cluster so long names ellipsize before the glyphs shift.
- `SidebarThreadRow` cleanup action overlays the status dot:
    - Show the archive/delete button only while the row is hovered or confirmation is armed; only pointer hover over the button itself shows the circular background — separate from selected-row and row-hover backgrounds.
    - The red `Confirm` pill is icon-height, expands left from the status column, and the whole rounded pill is the hit target; a timeout after hover leaves collapses the width without a fade.
    - **`sidebarThreadCleanupButtonVisibility` is the single source for which of the two renders**, and documents why they can never co-render. The `onHover` re-entry branch must clear `isCleanupControlCollapsing` (not only `isCleanupControlCollapsingToHidden`), or re-entry shows an empty hover circle for up to 180ms. Both `cleanupButtonContent` branches carry `.transition(.identity)` because the sibling width `withAnimation` in the same update pass governs the `ZStack` child's removal — `withTransaction(disablesAnimations:)` on the chrome flag alone left `Confirm` painted under the glyph for the full 0.18s.
    - **Dismiss instantly on confirm:** `clearCleanupConfirmation(forCommit: true)` drops the pill with no animation, because `onConfirmCleanup` removes the row and an animated collapse lags behind the `List` pulling the row out. The width-reset `Task` still runs so a failed archive/delete restores the hover glyph; the timeout path keeps its animation. The state machine lives in `SidebarView+ThreadRowCleanupConfirmation.swift`, which is why the `@State` it drives is internal on `SidebarThreadRow`.
    - Pause the confirmation timeout while the pointer is over the pill or pressed on it; resume when the press ends outside with hover gone.
    - Keep the 8pt title gap identical with and without the cleanup icon so hover does not change truncation.
- Thread names render via the shared `AppMarkdownInlineLabel`, which keeps plain rows and rows with inline-code or `@mention` chips at a uniform height (`testSidebarThreadRowChipAndPlainShareHeight`; mention chips snapshot-locked by `testSidebarThreadRowMentionTitleRendersChip`).
- Chip colors always use the `.standard` palette — uniform fill across selection transitions is the product decision. Do not reintroduce selection-aware chip swapping here by reaching past the label into `AppMarkdownInlineCodeChip(style: ...)`.
