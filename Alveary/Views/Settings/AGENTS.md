## Settings Screen

These instructions cover settings UI files under `Alveary/Views/Settings/`.

- Keep settings sections/tabs sorted alphabetically by their visible title everywhere they are displayed. `AppSettings.SettingsPage.allCases` drives the sidebar and compact picker, so update the enum case order, tab switch cases, presentation switches, and snapshots together when adding or renaming a settings tab. Adding a case shifts *every* `SettingsScreen` snapshot, not only the new tab's: wide baselines show the sidebar list and narrow ones show the segmented picker, and both enumerate `allCases`.
- Session-handoff settings live in the Handoff tab (`SettingsScreen+HandoffTabView.swift`), not Threads; do not reintroduce a `Context management` section to the Threads tab.
- Settings has no archived-threads surface. The sidebar `Archived` row and `Alveary/Views/Archived/` own that entirely; do not reintroduce an `Archived Tasks` section to the Threads tab.
- The Agents tab renders providers as `SettingsAgentCard` grid cells; the single refresh affordance lives in `SettingsScreenHeader` (Agents page only), so do not reintroduce per-card refresh buttons or a `Models` list.
- The `AGENTS.md` sub-section (`SettingsScreen+AgentsInstructionsSection.swift`) edits the shared `~/.agents/AGENTS.md` through `GlobalInstructionsEditorModel` and BlockInputKit. Keep the editor a plain markdown host: no completion provider, no slash commands, no drops, and a local `BlockInputStyle` rather than `BlockInputComposerStyle`. Save and Revert must stay behind confirmation dialogs, and link/copy migration actions delegate to `GlobalAgentInstructionsService`.
    - **Keep the editor host keyed and height-framed.** `AgentsInstructionsEditor` must read `model.contentGeneration` in `body` (via `.id`) — its only stored property is a reference whose pointer never changes, so without an observed read SwiftUI skips the body after async disk loads and the editor stays empty. It must also apply BlockInputKit's `onPreferredHeightChange` through an explicit `.frame(height:)`; `sizeThatFits` gets an unbounded vertical proposal inside the settings `ScrollView` and the editor balloons. Keep the default and maximum visible line counts equal so the height stays fixed — per-keystroke growth animates the whole section, and overflow already scrolls inside the editor.
