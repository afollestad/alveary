## Settings Screen

These instructions cover settings UI files under `Alveary/Views/Settings/`.

- **Build rows from the shared settings row types rather than hand-rolled stacks.** `SettingsFormSection` and `SettingsFormRow` keep section cards and row alignment consistent, `SettingsResponsiveControlRow` owns a label/control pair, and `SettingsToggleRow` owns booleans — it preserves switch styling, row-click toggling, press feedback, and accessibility actions. `SettingsControlHorizontalSizing` documents which controls fill and which hug.
- **Keep settings navigation reachable.** `SettingsScreen` switches from the side list to `SettingsScreenCompactNavigation` before the side list can be clipped, and that strip scrolls horizontally and scrolls the selection into view — the width threshold alone cannot keep every page reachable.
- Keep settings sections/tabs sorted alphabetically by their visible title everywhere they are displayed. `AppSettings.SettingsPage.allCases` drives the sidebar and the compact strip, so update the enum case order, tab switch cases, presentation switches, and snapshots together when adding or renaming a settings tab. Adding a case shifts *every* `SettingsScreen` snapshot, not only the new tab's: wide baselines show the sidebar list and narrow ones the chip strip, and both enumerate `allCases`.
- `AppSettings.suppressPullRequestLinkPrompts` deliberately has no settings row; it is written only by the transcript link prompt's `Never` action, and turning `Automatically link PRs` on is how the user gets out of it. Do not add a control for it.
- Session-handoff settings live in the Handoff tab (`SettingsScreen+HandoffTabView.swift`), not Threads; do not reintroduce a `Context management` section to the Threads tab.
- Settings has no archived-threads surface. The sidebar `Archived` row and `Alveary/Views/Archived/` own that entirely; do not reintroduce an `Archived Tasks` section to the Threads tab.
- The Agents tab renders providers as `SettingsAgentCard` grid cells; the single refresh affordance lives in `SettingsScreenHeader` (Agents page only), so do not reintroduce per-card refresh buttons or a `Models` list.
- The `AGENTS.md` sub-section (`SettingsScreen+AgentsInstructionsSection.swift`) edits the shared `~/.agents/AGENTS.md` through `GlobalInstructionsEditorModel` and `AppMarkdownEditor` (see `Alveary/Views/Components/TextInput/AGENTS.md`). Save and Revert must stay behind confirmation dialogs, and link/copy migration actions delegate to `GlobalAgentInstructionsService`.
    - **Keep the editor host keyed.** `AgentsInstructionsEditor` must read `model.contentGeneration` in `body` (via `.id`) — its only stored property is a reference whose pointer never changes, so without an observed read SwiftUI skips the body after async disk loads and the editor stays empty. It takes `.fixedLineCount` because it sits in the settings `ScrollView`.
- The Menu bar tab's `Launch at startup` row has no `AppSettings` key: macOS owns the login-item registration, so `SettingsViewModel` reads it back through `LaunchAtStartupService` after every write and on `NSApplication.didBecomeActiveNotification`. Do not persist a mirror of it.
    - **The packaged default is `InertLaunchAtStartupService`**, so a test or preview cannot add its own build to the developer's login items; production injects the real one in `ContentView+Factories.makeSettingsViewModel(dependencies:)`.
- The Git tab's `Agent` / `Model` / `Effort` pickers configure *both* agentic pull-request routes, so their labels name neither; the section header supplies "Pull requests" and the `Agent` row's help text names the two buttons. Their settings keys stay `pullRequestReview*` — see `Alveary/Services/Settings/AGENTS.md`.
- The five prompt rows (`SettingsScreen+PromptEditor.swift`) share one sheet across the Git and Handoff tabs. Its draft lives on the *row*, not the sheet, so the Edit action seeds it and nothing reaches the bound setting until Save. `SettingsPromptEditorSheet` is internal only so snapshots can host it. Authoring rules for the packaged defaults live in `Alveary/Services/Settings/AGENTS.md`.
