## Reasoning Popover

These instructions cover `Alveary/Views/Input/Reasoning/` — the model, effort, and speed popover, shared by the composer action row and the `ExitPlanMode` overlay panel. The row that anchors it is `Alveary/Views/Input/ActionRow/AGENTS.md`, which owns the rules every composer popover follows.

- **`ComposerReasoningMenuPresenter` owns the popover's lifecycle for every host.** Transient behavior, suppressed animation, anchor reuse on resize, and close bookkeeping live there so the two surfaces cannot drift. `ChatComposerActionRowView` keeps its `reasoning*` property names as forwarding onto the presenter, and a host that anchors the popover to itself must set `anchorView` alongside `anchorRect`.
    - **Keep the testing seams on the presenter.** `isPresentedOverride`, `presentationOverride`, `effortFocusOverride`, and `modelsFocusOverride` exist because `AlvearyTests/AGENTS.md` forbids live `NSPopover` host tests on macOS 26, and this popover resizes itself on disclosure expansion — the exact crash pattern. `popover`, `controller`, and `anchorRect` stay settable so tests can install a recording popover.
    - **A host with its own key handling claims unhandled dropdown keys through `ComposerCompactDropdownButton.keyEventHandler`.** `Return` and `Space` always stay with the dropdown, or a focused control could never be opened from the keyboard.
- **Reasoning controls are caller-owned inputs.** Render effort as the oversized snapping slider, models as an inline disclosure list grouped by provider only when multiple non-empty groups are present, and Fast as a separate toggle only when supported — `bolt` with enablement help while off, accent-tinted `bolt.fill` with disablement help while on. The compact reasoning button's active-only indicator is that same accent-tinted `bolt.fill` at its compact sizing and spacing.
- **Build model rows lazily on first disclosure expansion** (`hasBuiltModelRows` in `ComposerReasoningMenuView`). Collapsed opens and collapsed updates must not pay the per-model row build, and the first expansion must build synchronously before the immediate resize.
- **Resize the inline model list and the popover immediately when disclosure changes, and never animate the expansion.** Keep the rotating caret treatment and the pinned controls.
