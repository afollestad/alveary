# Pull Request Comment Surfaces

These instructions cover `Alveary/Views/PullRequests/Comments/` — the comment chrome both pane tabs and the transcript share, the BlockInputKit composer, the markdown sanitizer, the avatar view, and comment attachments.

**Keep a rule here only when the code that would violate it is not the code that documents it.** Mechanism whose only reader is its own file belongs in a doc comment: `PullRequestCommentBadge`, `PullRequestCommentAuthorRow`, `PullRequestCommentActionsMenu`, `PullRequestCommentRevealAction`, `PullRequestTimestampLabel`, `PullRequestResolvedThreadHeader`, `PullRequestThreadActionsFooter`, `PullRequestCommentEditor`, and `PullRequestAvatarView` each carry theirs.

## Comments And Threads

- **Sanitize GitHub HTML before markdown rendering.** `PullRequestMarkdown.sanitized(_:)` rewrites the tags GitHub allows (`<p>`, `<br>`, `<b>`, `<em>`, `<code>`, `<sub>`/`<sup>`, comments) into markdown, leaving fenced code blocks untouched. **Every** PR body, activity entry, and diff-thread comment renders through it, wherever it is drawn.
    - **It also marks every in-paragraph newline as a hard break**, because GitHub renders comment bodies that way and Foundation otherwise folds them into one wrapped flow. This is PR-scoped deliberately — chat transcripts keep standard CommonMark folding — so do not lift it into `Alveary/Views/Components/Markdown/Core/`.
    - **`<details>`/`<summary>`/`<section>` pass through deliberately** — the markdown layer owns them and renders a real collapsible block (`Alveary/Views/Components/Markdown/AGENTS.md`), and drops the tags it cannot express. Flattening the summary to bold here would reopen every section its author collapsed.
    - **Pass a per-comment `stateScope`** (`PullRequestCommentBody`) or `taskStateScope` (`AppMarkdownText`) at every site that renders a body. Disclosure and checkbox state is keyed by body text otherwise, so two comments carrying the same section open and close together.
- **Comment bodies render remote images.** `AppMarkdownText` shows standalone images as blocks and same-line images inline through the shared `AppMarkdownImageStore`; clicking a loaded block opens the app image preview modal (`ContentView+RightPane.swift` injects `\.appMarkdownImagePreviewAction`). Snapshot fixtures inject a preloaded store via `\.appMarkdownImageStore` or keep bodies image-free.
- **Comment composing is BlockInputKit.** The inline diff composer and the review footer share `PullRequestCommentEditor`, a thin `AppMarkdownEditor` wrapper. The shared rules — commit-point serialization, transition-only flag publishes, line-count sizing — live in `Alveary/Views/Components/TextInput/AGENTS.md`. What is specific here: mount-time focus relies on BlockInputKit's deferred window-attach handling, pinned by `PullRequestCommentEditorFocusTests`.
- **Never wrap `PullRequestCommentEditor` in a drop modifier.** `dropDestination`/`onDrop` on it — or on any ancestor between it and its host — re-propose sizes and silently collapse it by a visible line. Apply `pullRequestAttachmentDropTarget(isEnabled:onDrop:)` to the host's outer container and re-verify editor snapshots after touching the chain.
- **Pending and submitted comments are addressed differently — branch on `isPending` at every entry point.** Pending edits and deletes go over GraphQL by node id (`composerPendingCommentNodeID`); submitted ones over REST by `databaseId` (`composerRemoteCommentID`). Both tabs make the split, and missing it silently PATCHes `pulls/comments/{id}` for a pending comment. Deleting a pending comment skips the confirmation dialog — nothing is published — and `PendingRemoteCommentDeletion` is REST-only.
- **Comment affordances follow GitHub permissions, not authorship**, from `viewerCanUpdate`/`viewerCanDelete`; the shared menu offers only the permitted actions, on both tabs. Review cards get the same menu gated on the review's own `viewerCanUpdate`, **Edit only** — GitHub cannot delete a submitted review.
- **Every comment mutation is optimistic and owned by the view model.** `PullRequestsViewModel+RemoteComments.swift` documents each edit, delete, and reply flow at its entry point; what matters here is that only a successful *reply* refetches, and a delete arms a session-owned confirmation surfaced by one dialog on `PullRequestPane` rather than per row.
- **Threads reply and resolve on both tabs, through `PullRequestThreadActionsFooter`.** Changes opens the reply composer with a diff anchor; the Overview opens the anchorless overload and renders the editor inline, replacing the footer — `isReplyingInline` matches root comment id plus nil anchor so each tab shows only its own editor.
- **Pane snapshot fixtures must inject a fixed `now`** just after the fixture dates, or relative ages drift with the wall clock.

## Attachments

- **Attachments upload through the `gh-image` extension, never a token**, and `Alveary/Services/Git/GitHubCLI/AGENTS.md` owns why no token-based path can exist. **Do not add a cookie-reading path here**; a missing extension surfaces as a toast carrying the install command.
- **Uploads are placeholder-driven and view-model-owned**, so pane closure cannot cancel one — `PullRequestsViewModel+Attachments.swift` documents the placeholder swap and the unstructured task behind that. Save and Submit stay disabled while an upload runs, so a placeholder can never post.
- **Uploads seed the image caches; panes register their repository.** The upload reaches `attachmentImageSeeder` *before* placeholders are replaced, because the fresh asset is still session-gated on GitHub's side and must render from local bytes. `requestDetails` calls `attachmentImageRepositoryRegistrar` so `GitHubAttachmentImageURLResolver` can mint signed URLs for that repository's markdown; see `Alveary/Services/Git/GitHubCLI/AGENTS.md`.
- **A `sessionUnavailable` failure opens `PullRequestAttachmentAccessSheet`, not a toast** — the remedy is a privacy grant or browser sign-in, which a toast cannot walk the user through. `PullRequestsScreen` presents it from a lifted `.sheet(item:)` helper, and the sheet polls the Safari cookie-store probe each second for a green "Access granted" cue. Its paragraph `Text`s keep `fixedSize(horizontal: false, vertical: true)` or the layout compresses them into truncation.
