# Pull Requests List Screen

These instructions cover `Alveary/Views/PullRequests/List/` — `PullRequestsScreen` with its header, filter popover, sections, and load-more footer, plus `PullRequestRow` and its card background. `Alveary/Views/PullRequests/AGENTS.md` owns how the screen is reached and gated.

> **READ FIRST:** Focus and keyboard rules are centralized in **Focus And Keyboard Coordination** in `Alveary/Views/AGENTS.md`; the list-arrow focus bullet below stacks on top of that contract.

**Keep a rule here only when the code that would violate it is not the code that documents it.** Mechanism whose only reader is its own file belongs in a doc comment: `PullRequestRowCardBackground`, `PullRequestsSectionedList`, `PullRequestsLoadMoreFooter`, and `PullRequestsFilterPopover` each carry theirs.

- **Reuse the shared pane chrome.** The header is a `ResponsivePaneHeader` (tab chips + search + refresh + filter popover button); content padding reuses `PaneHeaderLayout.leadingInset`/`.trailingInset`. Both icon buttons stay inline at every width — they are already at the shared 30pt footprint, so only the chips and search give way. This is the widest of the five headers, so it reaches the ladder's lower rungs first.
- **Keep row inputs equal across passes.** Every value a row takes must be stable across renders: `visibleSections(for:)` is memoized and resolves once per body pass rather than inside the scroll content, and `referenceDate` is stored on the view model rather than read from the clock. Each of those once differed on every render, which made a click repaint every visible row before its own highlight could land.
    - The hoist-above-`GeometryReader` rule this follows lives in **Render Cost** in `Alveary/Views/AGENTS.md`.
    - **Do not move the `AppSelectableRowState` reads onto `PullRequestRow`.** The row would resolve the environment from above the modifier that publishes it and paint nothing until its model published; `PullRequestRowCardBackground` exists for that reason. Rows also draw their own card fill because `.appSelectableRow`'s selection chrome renders only inside a `List`, and these live in a `ScrollView`.
- **Rows are two lines.** Title over the avatar/author/repo/branch line on the left; relative age over +/- stats on the right; the status glyph vertically centered far left. Attribution texts hug their content — fixed `frame(maxWidth:)` reservations read as phantom columns.
- **Titles render inline markdown everywhere they appear**, since GitHub titles routinely carry backticked identifiers: `AppMarkdownInlineLabel` on single-line surfaces, `AppMarkdownInlineParagraph` where the pane header wraps, `AppKitMarkdownInlineString` in the transcript widgets. **Every one of them opts out of mention detection** and builds its accessibility label from `plainText(from:detectingFileMentions: false)` — see `Alveary/Views/Components/Markdown/AGENTS.md` for why. Filtering still matches the raw title, so a query spanning a backtick will not hit; that is deliberate, because the user types what they see.
- **"Load more" is a footer under the sections, not a row.** It mounts when the tab has sections and `canLoadMore(for:) || isLoadingMore` holds — `canLoadMore` alone goes false the instant a page is requested, since its buckets are in flight, which unmounted the footer before its spinner could render. **Keeping it out of the keyboard order is deliberate**, so arrow-key selection still walks only pull requests.
- **List arrows follow visual order.** The scroll content is `.focusable()`; Up/Down call `selectAdjacentRow(in:forward:)` in visual order and scroll the selection into view. Row clicks claim the same `@FocusState` so arrows work immediately after a click.
- **Status icons are tinted Primer Octicons**, matching GitHub: open green, draft secondary, merged purple, closed red. Merged purple comes from the `PullRequestMergedColor` asset (Primer's `#8250DF` light / `#A371F7` dark) because system `.purple` reads neon in dark mode. Color meaning follows the Status Dot Colors table in `Alveary/Views/AGENTS.md`; `accessibilityName` carries the state for non-color users.
- **Keep ages deterministic.** Relative ages come from `compactRelativeAge(from:relativeTo:)` fed by `viewModel.referenceDate`, so snapshots inject a fixed clock. Snapshot fixtures keep `authorAvatarURL` nil so the letter placeholder renders instead of fetching.
- **Sections come from `visibleSections(for:)`.** Reviewing splits "Pending review" above "Previously reviewed" — **a re-request counts as pending**, as it does in `Alveary/Services/PullRequests/HostTools/AGENTS.md`. The All tab buckets each row exactly once with Authored winning ties; Authored stays flat and untitled. Keyboard order is the flattened section order.
- **Rows sort by recency**, by `updatedAt` descending with `displayKey` breaking ties, client-side so every tab and section inherits it. **Status does not participate** — an explicit reversal of the earlier status-first order.
- **Status narrows the GitHub search; repository narrows the loaded rows.** That is the whole reason status is single-select (`Alveary/Services/PullRequests/GitHub/AGENTS.md` owns why it cannot be a set) while repositories are a set. `normalizeRepositoryFilter()` prunes vanished repositories while keeping survivors and never persists, so a repository absent from one fetch stays selected for the next launch; rows hide repository text only when the filter narrows to one. Snapshot the popover's content view directly — live popover hosts crash (see `AlvearyTests/AGENTS.md`).
    - **The filter button reads highlighted on a fresh install**, because `hasActiveMenuFilters` asks whether the list is narrowed and the packaged status default is `.open`. That is the affordance pointing at why merged and closed pull requests are absent; do not redefine it as "differs from the default" to quiet it.
- **Tab and filters persist through `AppSettings`**, restored in `init` and written only on explicit user actions. The tab is VM-owned (`selectedFilter`), not screen `@State`.
- **The search field's binding is raw; the list trails it.** `$viewModel.searchQuery` updates per keystroke, so typing stays responsive and the condensed search glyph tints at once, but the rows and the empty-state copy come from the debounced `activeSearchQuery` — which is invisible from the binding alone. `Alveary/ViewModels/PullRequests/AGENTS.md` owns the split.
- **Never surface task cancellation as an error.** Leaving the screen cancels the `.task` refresh; `refresh()` swallows `CancellationError` and checks `Task.isCancelled` before applying wrapped failures.
- **The error banner carries its own Retry.** It renders *over* rows that loaded, so the `.unavailable` state's Retry is not on screen and the header's refresh icon is not a discoverable recovery from a red banner. Both call `viewModel.retry()`, which clears `errorMessage` too — leaving the message up would read as the retry failing instantly.
