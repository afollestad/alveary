## Runtime Tool Approval

These instructions cover `Alveary/Services/Agent/Runtime/ToolApproval/` — how a tool approval reaches the provider, on the live hook path and through fallback deferral. `Alveary/Services/Agent/Runtime/AGENTS.md` owns the rest of runtime management and the notification gating an approval triggers; `Alveary/ViewModels/Conversation/Approvals/` owns the UI half — which approvals batch, which supersede, and what blocks the composer. AgentCLIKit owns hook transport and provider approval policy.

> **READ FIRST — the state these rules govern is not all in this folder.** `EventBuffer` holds `pendingLiveToolApprovals`, `resolvedLiveToolApprovals`, and `hasDeferredToolStop`; `DefaultAgentsManager+AgentCLIKitBuffers.swift` seeds them, `+StreamEvents.swift` sets the deferred-stop flag, and `+AgentCLIKitStatus.swift` reads it. Trace a counter or flag through those before assuming this folder is its only writer.

**Keep a rule here only when the code that would violate it is not the code that documents it.** Mechanism whose only reader is its own file belongs in a doc comment: `requiresProviderRestart`'s demotion to deferred and both of its bookkeeping exceptions, the grace-window wait before escalating to `kill`, the post-respawn interaction resolution, the missing-marker nudge, and why a respawned Codex process can never replay each carry theirs.

- **Keep the runtime alive for live approval.** A live hook approval emits its `tool_approval` event without stopping the provider process, setting `hasDeferredToolStop`, or ending the active turn — the process is blocked inside the hook request and continues once the hook response is recorded.
- **Let AgentCLIKit own deferred-stop teardown.** Never kill the process from Alveary when the stream reports a deferred stop. AgentCLIKit closes stdin so the provider can flush its deferred-tool session records before exiting, and an early kill races the `hook_deferred_tool` write — without that marker Claude's resume never re-runs the deferred tool, and the turn hangs.
- **Keep deferred buffers replayable.** The stop can land after the conversation view unsubscribed, such as when the user starts another thread. Preserve the event buffer with replay enabled so a later view activation still persists the `tool_approval` row to SwiftData.
- **Ignore trailing events from that runtime.** Once a stream generation emits a deferred-tool stop, drop every later event from the same live process, or buffered fallback chatter leaks into the transcript before teardown completes.
- **Resume fallback deferrals in the same session.** Record the decision through `claudeApprovalPolicyStore.recordTransientDecision(...)`, then respawn with `forkSession: false`. Live hook approval instead resolves the held request through `liveHookDecisionProvider`.
- **Forward `ClaudeToolApprovalResolution.responseText` only for `ExitPlanMode`.** Live, deferred, future-live, and app-native interaction resolution all pass it through; every other denial, including a sibling swept up in the same decision, keeps the generic reason.
- **Keep resolved approvals idempotent.** AgentCLIKit suppresses the retained transcript frames it replays after a deferred resume, but `resolvedLiveToolApprovals` is what stops Alveary re-publishing one it already answered. `prepareForApprovalResumeIfNeeded` in `Alveary/ViewModels/Conversation/Approvals/` owns draining the resume cursor before subscriptions reset.
- **Track a cancelled interaction by ID *and* runtime generation.** `AskUserQuestion` and `ExitPlanMode` denial or dismissal map to cancelled interactions; without the generation, stale waiting, running, or failure status from that turn reopens waiting UI or strands the conversation busy. Clear the marker on new sends, new generations, or unrelated interactions.
