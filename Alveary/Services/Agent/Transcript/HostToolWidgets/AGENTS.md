## Host Tool Widgets

These instructions cover `Alveary/Services/Agent/Transcript/HostToolWidgets/` — the descriptor catalog, the durable `HostToolWidgetEntry` a card renders from, the per-feature parsers and summary copy, and the grouper companion that routes calls, results, and outcome markers to them. `Alveary/Services/Agent/Transcript/AGENTS.md` owns the rest of grouping, `Alveary/Views/Chat/Blocks/AppKit/Widgets/AGENTS.md` owns the cards these entries render as, and `Alveary/Services/HostMCP/AGENTS.md` owns enrolling the tool itself.

**Keep a rule here only when the code that would violate it is not the code that documents it.** Mechanism whose only reader is its own file belongs in a doc comment: `HostToolTranscriptCatalog`'s extension points and each descriptor's reason for having a card, `HostToolWidgetEntry.openableTarget` and `isSettledWithoutDecision`, `HostToolWidgetSummary`'s tense rules, and the grouper companion's call routing, result patching, and keyless-marker pairing each carry theirs.

- **A lookup whose result only reports stays an ordinary tool row.** A card earns its place by needing affordances the row cannot give — a confirmation decision, or rows that each open something different. `HostToolTranscriptCatalog` is the list, and each descriptor's comment says why it is an exception; do not keep a second list here.
- **Do not assume structured tool output.** Claude persists `JSON.stringify(structuredContent)` as the result text while Codex persists the plain-text fallback, and both reach the transcript. Only an explicit error is a failure — a result that will not parse still took effect. `Alveary/Services/HostMCP/AGENTS.md` owns the writing half: every tool fills both fields, and the provider picks which one it persists.
- **A parser may decline a call, but never its result.** Returning `nil` for a landed result leaves the card stuck running while the answer arrives in a message beneath it. Model "cannot render this payload" as a landed case with its own copy — `PullRequestListWidgetContent.listedWithoutRows` is the example.
- **Prefer the request's own fields to parsing the host's message.** Take a message fallback only where a text-fallback provider would otherwise leave the card unable to name its target, and never when a structured receipt parsed, whose absent field genuinely means there is nothing to name.
- **Descriptors answer to both reported tool-name shapes** through the shared `matches(toolName:)`; never add a per-descriptor name check. `Alveary/Services/HostMCP/AGENTS.md` owns the matching mechanism.
- **Features write `host_tool_outcome` markers through `HostToolWidgetOutcomeMarker`** — `ScheduledTaskProposalOutcomeRecorder` and `PullRequestReviewProposalOutcomeRecorder` today. `Alveary/Data/AGENTS.md` owns the record type and `Alveary/Services/Scheduled/HostTools/AGENTS.md` the save ordering a writer must follow.
    - **Always set the marker's `toolName`.** A marker whose key matches no widget is paired by scanning them, and an unnamed one matches any feature's card — reporting a decision the user never made.
