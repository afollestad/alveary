## Settings Services

These instructions cover the settings services under `Alveary/Services/Settings/`.

- `.alveary.json` writes are a selective round-trip, not a wholesale rewrite. The project settings editor only owns `scripts.setup`, `scripts.teardown`, `preservePatterns`, and `actions`; when saving supported config, preserve non-editable supported fields such as `scripts.setupTimeoutSeconds` and `shellSetup` instead of dropping them. If the merged supported config normalizes to no meaningful values, delete `.alveary.json` instead of persisting an empty `{}` file.
- Read `.alveary.json` for a UI surface through `ProjectConfigStore.shared`, not `AlvearyProjectConfig(projectPath:)` directly. Selecting a project row mounts the settings editor and loads the toolbar's project actions on the same frame; going through the store makes that one read, and its synchronous `cached(forProjectPath:)` lets both render populated on the selection frame instead of blanking. Background flows that need disk truth regardless (worktree setup) may still read directly.
    - **It caches, it does not watch.** The store learns about writes the app makes. A surface that must reflect an edit from outside the app calls `reload(forProjectPath:)`; the settings editor does, the toolbar does not.
    - **It owns the change notification.** `apply` posts `.projectConfigDidChange` whenever a cached value is *replaced* by a different one, so a stale reader catches up. A first load posts nothing — no reader can be stale yet. Do not post that notification from anywhere else.
- **Packaged prompt defaults must round-trip through `AppMarkdownDraft` byte for byte.** `SettingsPromptEditorSheet` edits them with BlockInputKit and commits serialized markdown, so a default that reformats gains blank lines the first time a user opens it and presses Save, and leaves Reset enabled on untouched text. `PromptDefaultsMarkdownRoundTripTests` is the guard; the editor's own rules live in `Alveary/Views/Components/TextInput/AGENTS.md`.
    - **One *prompt* line per paragraph and per list item.** A real line break is what breaks this: an indented continuation line parses as its own paragraph rather than joining the item above it, and even a mid-paragraph break renders as a hard break in the editor and the transcript card. Keep source lines under the lint limit with `\#` string continuations, which join without emitting a newline.
    - **Blank line between a paragraph or heading and a following list**, none between sibling list items, and exactly two spaces per nested-bullet level — that is what the serializer emits.
    - **Backtick every tool name.** Markdown reads the underscore pair in `get_pr_timeline` as emphasis and renders it "get*pr*timeline" in both the editor and the transcript's review-instructions card.
    - Changing a default reaches only fresh installs and explicit Reset; existing users keep their persisted copy.
- Persisted UI enum/string settings should decode missing or invalid values to their packaged defaults instead of failing settings load.
- Persisted UI numeric settings should decode missing values to defaults and clamp invalid values to their supported ranges.
- `rightPaneWidth` is one persisted width for the whole right-pane lane, clamped to `320...960` and defaulting to `380`. Diff, Skills, MCP, Scheduled, and Pull requests each stored their own before; switching panes then resized the *main* pane, which re-wrapped chat bubbles the user had not touched. Do not reintroduce a per-destination width. The retired keys live on in `LegacyCodingKeys` for decode only — `diffViewerWidth` seeds the shared value and re-encoding drops all five.
- Screen tab selections (`pullRequestsSelectedTab`, `scheduledTasksSelectedTab`) persist as raw tab-title strings; a stored value that no longer names a tab falls back to the packaged default at the restore site. The Pull Requests filter sets (`pullRequestsStatusFilters`, `pullRequestsRepositoryFilters`) persist alongside them; unknown status strings drop out element-wise during decode.
- Agentic-review agent settings (`pullRequestReviewProvider`/`Model`/`Effort`) are optional, and `nil` means "follow the Threads tab's defaults" — a narrower claim than `AppSettings.defaultModelValue`, which means the provider's own default model. Normalization only trims them and drops an unsupported provider; model and effort are runtime-validated against provider discovery when the review spawns, so a stale value survives here and coerces there.
